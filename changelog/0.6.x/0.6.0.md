# 0.6.0 — 2026-09-24

## Changed

- **`met_search_collections` calls `/v1.1/search`** ([#27](https://github.com/cyanheads/met-museum-mcp-server/issues/27)) ahead of `/v1/search`'s 2026-10-01 retirement: `offset`/`limit` pass upstream, one request per page, and the unfiltered control run is gone. `remaining`, `truncated`, and `nextOffset` count against `min(total, 10,000)`, and a `notice` names the window when `total` exceeds it.
- **`content[]` page markers**: `(truncated)`, `(complete)`, `(window end)` for a last page stopped at 10,000 short of `total`, and `(offset beyond result set)`.
- **Breaking: `isPublicDomain` removed from `met_search_collections`** ([#27](https://github.com/cyanheads/met-museum-mcp-server/issues/27)); `/v1.1` ignores it, so passing it is now a schema rejection. Verify CC0 status per object from `isPublicDomain`/`hasCC0Image` on `met_get_object`.
- **Breaking: `geoLocation` accepts one value** ([#27](https://github.com/cyanheads/met-museum-mcp-server/issues/27)); `/v1.1` applies only the first, so a multi-value array is rejected. Pass a one-element array such as `["France"]`.
- **Breaking: `MET_BASE_URL` default is now `https://collectionapi.metmuseum.org/public/collection`** ([#27](https://github.com/cyanheads/met-museum-mcp-server/issues/27)); each endpoint appends its own version. Existing values ending in `/v1` (or `/v1.1`) still resolve.
- **`no_results` recovery names the filters that zeroed the query** ([#25](https://github.com/cyanheads/met-museum-mcp-server/issues/25)), keyed on one keyword-only `limit=1` count issued only on a filtered zero; a `medium` value gets its case-sensitive-classification correction. A caller abort during that count ends the call as cancelled.
- **Tool descriptions and server `instructions`** drop the partial-index and unchecked-page caveats, state the 10,000-match window, and spell `medium` examples as the Met does (`"Sculpture"`).
- **Release process**: `CLAUDE.md`/`AGENTS.md` declare the gated release-PR mode.

## Fixed

- **Breaking: the `search_timeout` error reason is removed** ([#28](https://github.com/cyanheads/met-museum-mcp-server/issues/28)); an upstream 504/408/425 or a request-timer abort now takes the ordinary retry path and surfaces as the upstream or `Timeout` error. Callers matching `search_timeout` should match the error code instead.
