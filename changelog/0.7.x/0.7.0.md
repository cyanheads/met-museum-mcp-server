# 0.7.0 — 2026-09-30

## Added

- **`met_list_objects`** ([#26](https://github.com/cyanheads/met-museum-mcp-server/issues/26)) browses `/v1/objects` by `departmentId`, `updatedSince` (`YYYY-MM-DD`, the day included), or both, returning ascending IDs paged by `offset`/`nextOffset` with no depth limit. Each list is cached for up to an hour, so a very recent revision may not appear yet.
- **`MET_CALL_DEADLINE_MS`** (default `30000`, [#22](https://github.com/cyanheads/met-museum-mcp-server/issues/22)) gives each tool call one wall-clock budget, shared by every Met API request, retries and backoff included. Expiry is `Timeout` with `data.reason: 'retry_deadline_exceeded'`; in `met_get_object` it lands per ID in `failed[]`.

## Changed

- **Error envelopes carry `data.requestId`**, `content[]` closes with `(reason … · request <id>)`, and a declared recovery hint now reaches service-layer failures too (mcp-ts-core 0.13.10).
- **Tool descriptions and server `instructions`** name `met_list_objects` as a browse path and a source of object IDs; `artistBeginDate`/`artistEndDate` descriptions cover a firm's founding or closing year and full dates.
- **Docker image** installs production dependencies in a `$BUILDPLATFORM` `deps` stage, cross-installed for the target, so a multi-arch build no longer runs Bun under QEMU.
- **Packaging and tooling**: the npm tarball excludes `dist/*.mcpb`; the lint, release, and skill-version scripts and `framework-skills/` sync to mcp-ts-core 0.13.10.
- **Docs**: README, `.env.example`, and `docs/design.md` cover the new tool and error reasons, record Decisions #18–#19, reverse Decision #6, and list the framework's `LOG_TOOL_FAILURE_PAYLOADS` and per-signal OTLP endpoint variables.

## Fixed

- **A Met firewall HTTP 403 fails as `upstream_blocked`** ([#31](https://github.com/cyanheads/met-museum-mcp-server/issues/31)): `ServiceUnavailable`, not retryable, with a wait-and-send-fewer-requests recovery on every tool. In `met_get_object`, IDs queued behind the block fail with it and are never requested.
- **A cancelled `met_get_object` call ends as cancelled** ([#22](https://github.com/cyanheads/met-museum-mcp-server/issues/22)), not as a partial success listing the cut-off IDs in `failed[]`.
- **Placeholder `artistEndDate` years** ([#29](https://github.com/cyanheads/met-museum-mcp-server/issues/29)) — a bare year after the current UTC year, such as `9999` or `2112` — normalize to `''`, and `content[]` renders a one-sided artist-date range open (`1837–`, `–1890`).
- **HTML entities in `constituents[].name` are decoded** ([#24](https://github.com/cyanheads/met-museum-mcp-server/issues/24)): `Tiffany &amp; Co.` reads `Tiffany & Co.`. Only the five XML-predefined names and decimal/hex references decode.
- **Raw `<i>`/`</i>` tags are stripped** ([#32](https://github.com/cyanheads/met-museum-mcp-server/issues/32)) from every free-text field of a `met_get_object` record, in `structuredContent` and `content[]` alike.
