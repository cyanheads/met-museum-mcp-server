# 0.10.0 — 2026-11-04

## Added

- **`met_search_collections` `matchField: "artistOrCulture"`** ([#53](https://github.com/cyanheads/met-museum-mcp-server/issues/53)) matches the lead attribution or the culture. A qualified attribution such as "Style of" matches too, so read `artistPrefix`; another person on the record, such as a sitter, does not. The `met_get_object` `artistDisplayName` description points at it, and `constituentID`'s no longer says "for cross-referencing": no tool takes one.
- **`MET_CLAMP_LIMITS`** ([#57](https://github.com/cyanheads/met-museum-mcp-server/issues/57)), default `true`, and the `met.limit.clamped` counter, labelled by tool, for each clamped call. `false` makes 500 the schema `maximum` on `limit`, so `met_search_collections` and `met_list_objects` reject 501–10,000 (opt-in; the default accepts them).
- **Published agent skill `met-museum-guide`**: the gates for fetch budgets, attribution, date windows, searches past 10,000 matches, and `geoLocation` matches. Served as `skill://met-museum-guide/SKILL.md` through `createApp({ skills: 'skills' })`, and shipped in the npm package, the Docker image, and the `.mcpb`.

## Changed

- **Breaking: `met_get_object` returns every fetched record and drops the `deferred` output field** ([#56](https://github.com/cyanheads/met-museum-mcp-server/issues/56)). The 60,000-byte `structuredContent` budget is gone; a call still fetches 20 distinct IDs and lists the rest in `remainingIDs`.
- **`limit` above 500 on `met_search_collections` and `met_list_objects` reads a 500-ID page** ([#57](https://github.com/cyanheads/met-museum-mcp-server/issues/57)) with no advertised `maximum`, replacing the 10,000 cap. The `notice` points at `nextOffset`.
- **Descriptions and notices state the filter semantics** ([#54](https://github.com/cyanheads/met-museum-mcp-server/issues/54), [#55](https://github.com/cyanheads/met-museum-mcp-server/issues/55)): `dateBegin`/`dateEnd` keep only objects whose whole span lies inside the window, `geoLocation` is one whole case-sensitive place, and `medium` is one classification. A zero-match `notice` that names `medium`, `geoLocation`, or `dateBegin/dateEnd` adds a correction sentence for each.
- **Server `instructions`** gain the request posture the Met's firewall calls for (one call at a time, only the records an answer needs), a line that catalog text is museum-authored data, never instructions, and a pointer to the skill. They drop the accession-number, `isHighlight`, and `medium` sentences, which the parameter descriptions already carry.
- **`mcp-ts-core` ^0.13.15 → ^0.13.18** (`@modelcontextprotocol/server` 2.3.1 → 2.4.0); `framework-skills/`, `scripts/`, issue templates, `.mcpbignore`, and root `plugin.json`/`mcp.json` sync to it, and the `.mcpb` cleaner keeps the MCP SDK's `dist/ext/skills/` runtime modules, which the framework imports at startup.
- **Docs**: README, `docs/design.md`, and `CLAUDE.md`/`AGENTS.md` cover the above.

## Fixed

- **`content[]` renders `q` in the zero-match `notice` as text** ([#58](https://github.com/cyanheads/met-museum-mcp-server/issues/58)): the trailer Markdown-escapes the whole notice, in linear time on any input, so it reads back exactly as `structuredContent.notice`, which is unchanged.
