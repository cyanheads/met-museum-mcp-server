# 0.10.1 — 2026-11-14

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.18 → ^0.13.22**; `framework-skills/`, `scripts/`, the changelog template, `.env.example`, and `CLAUDE.md`/`AGENTS.md` sync to it. What a caller or operator sees:
  - The `upstream_rate_limited` error trailer names the Met's `Retry-After` when it sent one: `(reason upstream_rate_limited · retry after <value>)`.
  - Startup fails with a `ConfigurationError` on an `MCP_HTTP_ENDPOINT_PATH` with no single reading (a full URL, `?`, `#`) or an `MCP_PUBLIC_URL` that is not an `http(s)` base URL without query, fragment, or user info, and exits 1 on Node.js below 24.
  - `engines.bun` rises to `>=1.4.4`.
  - Under `MET_CLAMP_LIMITS=false`, an argument rejection names the failed check (`limit: Too big: expected number to be <=500`) instead of a type hint. Which calls validate is unchanged.
  - `data.body` and `data.responseBody`, the upstream error page, stay out of every client envelope; `MetService` no longer strips them itself.

## Fixed

- **`met_get_object` keeps the line breaks of a multi-line `dimensions` value in `content[]`** ([#62](https://github.com/cyanheads/met-museum-mcp-server/issues/62)), each as a hard break, so `Image:` and `Mount:` read as separate lines. `structuredContent` is unchanged. The search `notice` and `dimensions` render through the framework's `escapeMarkdownInline`, linear in its input since mcp-ts-core 0.13.19, and the local `escapeMarkdownInlineLinear` wrapper is gone.
- **Every other `met_get_object` and `met_list_departments` field in `content[]` reads back as written.** A value ending in spaces or line breaks no longer ends its line in a hard break that pulls the next field onto it, and an entity reference in a value (`&amp;`, `&copy;`) is no longer read as the character. `|` and `~` are now escaped and an intraword `_` and a lone `<` are not; read-back is unchanged for those.
- **`medium` is described as the Met's object-type grouping, not the `classification` field** ([#61](https://github.com/cyanheads/met-museum-mcp-server/issues/61)): a match's `classification` can be empty or name another type, and one object matches several values, so counts split by `medium` can overlap. The `met_search_collections` and `met_list_objects` descriptions, the zero-match and blank-`medium` messages, the `met_get_object` `objectName` and `classification` descriptions, the README, `docs/design.md`, and the `met-museum-guide` skill (a new `medium` gate and a multi-word `artistOrCulture` bullet) say so.
