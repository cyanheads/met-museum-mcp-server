# 0.4.0 — 2026-09-09

## Changed

- **`content[]` text is Markdown-escaped at the render boundary:** upstream catalog text (title, credit line, tags, constituent names, and more) is escaped in `met_get_object` and `met_list_departments` before interpolation, so a value carrying Markdown syntax — such as the Met's bracketed cataloger titles for anonymous photograph groups — can no longer restructure or hide text in `content[]`-only clients. `structuredContent` is unchanged. URL-shaped fields (`objectURL`, image URLs, Wikidata/AAT/ULAN links) are validated as `http`/`https` before rendering as link destinations rather than escaped — a non-URL value (e.g. `(not assigned)`) renders as prose instead. ([#18](https://github.com/cyanheads/met-museum-mcp-server/issues/18))

## Fixed

- **`met_get_object`'s `objectBeginDate`/`objectEndDate` are now `number | null`:** the Met's `0`/`0` sentinel for "no machine-readable date" no longer passes through as a fabricated year-zero range — both fields normalize to `null` and the `content[]` **Date:** line renders `objectDate` alone when the range is unknown. Callers that read these fields as guaranteed non-null numbers need a null check. ([#14](https://github.com/cyanheads/met-museum-mcp-server/issues/14))
- **Null tag URLs no longer fail the whole object:** a `tags[]` entry with a null `AAT_URL` or `Wikidata_URL` — which the Met sends for a term with no Getty/Wikidata record — now normalizes to the server's existing empty-string absence convention instead of failing output-schema validation and discarding the entire object. ([#19](https://github.com/cyanheads/met-museum-mcp-server/issues/19))
