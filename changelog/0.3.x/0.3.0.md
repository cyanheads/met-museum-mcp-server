# 0.3.0 — 2026-09-09

## Added

- **`offset` output field:** `met_search_collections` echoes the resolved offset the page was read from, so a caller can compare it against `total` to tell an out-of-range offset from a genuine final page. ([#17](https://github.com/cyanheads/met-museum-mcp-server/issues/17))

## Changed

- **`isPublicDomain` and `isHighlight` are `true`-only:** the upstream index is unsound on `false` — it returns objects whose own record contradicts the filter — so both parameters now reject `false` at the schema instead of forwarding it. ([#12](https://github.com/cyanheads/met-museum-mcp-server/issues/12))
- **`no_results` recovery:** when `isPublicDomain: true` zeroed the query, the hint now names the filter and points to `met_get_object`'s `isPublicDomain` field instead of the generic broaden-the-query text. ([#20](https://github.com/cyanheads/met-museum-mcp-server/issues/20))
- **`format()` completion marker:** an empty page from an offset at or beyond `total` now renders `(offset beyond result set)` instead of the misleading `(complete)`. ([#17](https://github.com/cyanheads/met-museum-mcp-server/issues/17))

## Fixed

- **Blank filter values:** a whitespace-only `q`, a blank `medium`, an empty `geoLocation` array, or a blank `geoLocation` element now throw a declared `invalid_filter` error instead of being silently forwarded upstream (where a blank value returns an arbitrary, non-baseline result set) or dropped client-side (silently widening the search). ([#13](https://github.com/cyanheads/met-museum-mcp-server/issues/13))
