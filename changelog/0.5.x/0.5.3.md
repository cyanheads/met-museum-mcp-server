# 0.5.3 — 2026-09-19

## Added

- **`met_search_collections` accepts `query` or `keyword` for `q`; `met_get_object` accepts `ids` for `objectIDs`** ([cyanheads/mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452)), rewritten before validation via `inputAliases` — the advertised `inputSchema` is unchanged.

## Changed

- **An out-of-schema argument now returns `InvalidParams` (`-32602`)** instead of `ValidationError` (`-32007`) ([cyanheads/mcp-ts-core#416](https://github.com/cyanheads/mcp-ts-core/issues/416)).
- **Tool error `content[]` closes with `(reason … · not retryable)`** ([cyanheads/mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)) whenever a declared reason or `retryable` is set; `structuredContent` is unchanged.
- **`no_results`, `all_not_found`, and the search filter/date-range validation reasons log below `error`** ([cyanheads/mcp-ts-core#380](https://github.com/cyanheads/mcp-ts-core/issues/380)) — `notice` for a modeled zero-match outcome, `warning` for a caller input mistake. Server-side only; the wire envelope a client receives is unchanged.
