# 0.5.0 — 2026-09-09

## Added

- **`met_get_object` returns `geography` (nine findspot fields beyond `country`/`region`) and `measurements` (structured element measurements, numeric counterpart to `dimensions`):** both default to empty/null when the Met records nothing. The tool's advertised listing grows from 9,946 to 14,375 bytes (~44%) with these fields plus the `deferred[]` addition below — every client pays that on every session before making a call. ([#16](https://github.com/cyanheads/met-museum-mcp-server/issues/16))

## Fixed

- **`met_get_object` batch responses are now bounded by a cumulative 60,000-byte budget measured on `structuredContent`:** records are admitted whole in request order until one would exceed it; the rest come back in a new `deferred[]` array with their sizes instead of blowing out the response. A caller that assumed returned-record count equals requested count minus failures now gets fewer records than before on an unchanged heavy call — check `deferred[]` and re-request. ([#15](https://github.com/cyanheads/met-museum-mcp-server/issues/15))
- **Duplicate `objectIDs` in one call are de-duplicated,** fetched and returned once at the first occurrence's position — previously a repeat was fetched twice, charged to the byte budget twice, and could land in both `objects[]` and `deferred[]`. ([#15](https://github.com/cyanheads/met-museum-mcp-server/issues/15))
