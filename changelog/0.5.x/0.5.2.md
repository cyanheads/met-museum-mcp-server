# 0.5.2 — 2026-09-13

## Added

- **`createApp({ sessionMode: 'stateless' })`** declares the HTTP session posture in `src/index.ts` instead of leaving it to `MCP_SESSION_MODE` ([cyanheads/mcp-ts-core#376](https://github.com/cyanheads/mcp-ts-core/issues/376)). No tool here calls `ctx.requestInput`, so an unset variable now resolves to stateless rather than the framework's `auto` → stateful default; an explicit `MCP_SESSION_MODE` still overrides.
- README documents `met_search_collections`'s typed error reasons (`no_results`, `invalid_date_range`, `invalid_filter`, `invalid_department`, `search_timeout`) and `met_get_object`'s `deferred[]` byte-budget disclosure.

## Changed

- **Bun engines floor raised to `>=1.4.0`** (was `>=1.3.0`).
- **Dev skill tree moved from `skills/` to `framework-skills/`** ([cyanheads/mcp-ts-core#428](https://github.com/cyanheads/mcp-ts-core/issues/428)) — plugin installs no longer receive development skills. Path references synced across `framework-skills/`, dev scripts, `CLAUDE.md`/`AGENTS.md`, `.mcpbignore`, community templates, and the plugin manifests.
- **Internal:** `build`/`rebuild` pin `--project tsconfig.build.json` — the synced `scripts/build.ts` now defaults to `config/tsconfig.build.json` ([cyanheads/mcp-ts-core#432](https://github.com/cyanheads/mcp-ts-core/issues/432)), a path this repo doesn't use; `audit:fix` (`bun audit fix`) added alongside `audit:refresh`.

## Fixed

- HTTP transport closes a cancelled request's SSE stream immediately instead of holding it open for keep-alive ([cyanheads/mcp-ts-core#401](https://github.com/cyanheads/mcp-ts-core/issues/401)).
- Empty and whole-value unsubstituted `${…}` env values now read as unset rather than as literal text ([cyanheads/mcp-ts-core#427](https://github.com/cyanheads/mcp-ts-core/issues/427)); this server's `parseEnvConfig`-based config (`src/config/server-config.ts`) now falls back to its default on a blank env var instead of failing on the literal string.
- SIGTERM/SIGINT now end the process explicitly after graceful shutdown instead of waiting on the event loop ([cyanheads/mcp-ts-core#435](https://github.com/cyanheads/mcp-ts-core/issues/435)) — verified exit `0` on this build.
