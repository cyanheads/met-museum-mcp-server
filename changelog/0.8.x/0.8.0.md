# 0.8.0 — 2026-10-04

## Added

- **`met_get_object` `includeImages`** ([#36](https://github.com/cyanheads/met-museum-mcp-server/issues/36), default `false`) attaches the `primaryImageSmall` of the first 3 returned CC0 records as `content[]` image blocks, each after a caption, and reports every returned record in `images[]` (`attached`, `no_cc0_image`, `over_cap`, `unavailable`). Images come only from `https://images.metmuseum.org` and never enter `structuredContent`.
- **`artistPrefix`, `artistSuffix`, `artistRole`** ([#38](https://github.com/cyanheads/met-museum-mcp-server/issues/38)) on every record; the Artist line renders the full attribution (`Style of Rembrandt`) and ends with `| **Artist role:** <role>`.
- **`rightsAndReproduction`, `metadataDate`, `accessionYear`** ([#41](https://github.com/cyanheads/met-museum-mcp-server/issues/41)) on every record, `''` when absent, rendered as `**Rights:**`, `**Metadata date:**`, and `**Accession year:**`. `metadataDate` is the timestamp `met_list_objects` `updatedSince` compares.
- **`departmentId` on records** ([#42](https://github.com/cyanheads/met-museum-mcp-server/issues/42)), resolved from `department` through an exact map of the 19 `met_list_departments` names plus the five names records carry instead; `null` for a name the map does not hold.
- **`met_search_collections` `matchField`** ([#35](https://github.com/cyanheads/met-museum-mcp-server/issues/35)): `"title"` or `"tags"` restricts the keyword match, sent as `title=true` or `tags=true`. It composes with every filter and has no effect when `q` is `"*"`.
- **`effectiveQuery`** ([#44](https://github.com/cyanheads/met-museum-mcp-server/issues/44)) on every `met_search_collections` and `met_list_objects` success: the applied inputs as `name=value` pairs with JSON-encoded values, paging left out, or `no filter (whole collection)`.
- **`upstream_unavailable`** ([#33](https://github.com/cyanheads/met-museum-mcp-server/issues/33)) on every tool: a retry ladder that ends on HTTP 500, 502, 503, or 504 fails as `ServiceUnavailable` with `data.status` and the upstream `retryAfter` when sent, and a wait-a-few-minutes recovery.

## Changed

- **Breaking: `met_search_collections` answers zero matches as a success** ([#44](https://github.com/cyanheads/met-museum-mcp-server/issues/44)): `total: 0`, `objectIDs: []`, and the keyword-or-filters guidance in `notice`. The `no_results` reason (NotFound, `-32001`) is gone; read `total` and `notice` instead.
- **Breaking: a persistent HTTP 504 ends as `upstream_unavailable` (`-32000`)** ([#33](https://github.com/cyanheads/met-museum-mcp-server/issues/33)) instead of `Timeout` (`-32004`); the retry ladder itself is unchanged.
- **`met_get_object` stops feeding a Met outage** ([#33](https://github.com/cyanheads/met-museum-mcp-server/issues/33)): once a fetch ends on a 5xx and the Met has answered no ID in the call, IDs not yet started fail unrequested, capping an outage at `MET_BATCH_CONCURRENCY` × 4 requests. A batch that fetched nothing throws `upstream_unavailable` before `all_failed`.
- **`met_get_object` not-found guidance**: the `all_not_found` recovery and the per-ID not-found text tell the caller to drop IDs the object endpoint no longer serves, instead of re-checking them with `met_search_collections`; `all_failed` likewise says to drop an ID that keeps failing.
- **`q` description and server `instructions`** ([#43](https://github.com/cyanheads/met-museum-mcp-server/issues/43)) cover `"*"` as a match-all for filter-only searches and an accession number as a lookup that ranks its object first.
- **Field descriptions**: `primaryImageSmall` is about 600 px on the long edge, `department` names the five record names that differ from `met_list_departments`, and `updatedSince` names `metadataDate`.
- **Docker image** prunes musl-only native packages after the production install, since the glibc runtime never loads them.
- **Tooling**: devcheck, `lint-packaging`, and `framework-skills/` sync to mcp-ts-core 0.13.11; `.gitignore` and `.dockerignore` cover every `.env` variant and the MCP registry token files; CodeQL runs one job per language.
- **Docs**: README and `docs/design.md` cover the new inputs, fields, and error reason, record Decisions #20–#22, and reverse Decision #4.

## Fixed

- **Departments 7 and 17 return only their own objects** ([#39](https://github.com/cyanheads/met-museum-mcp-server/issues/39)): each `met_search_collections` page keeps the requested department's IDs from its cached `/v1/objects` list, while `total` and paging still count the Met's combined set. A notice says so, or that the filter could not be applied.
- **`met_list_objects` `updatedSince` before `1753-01-01`** ([#40](https://github.com/cyanheads/met-museum-mcp-server/issues/40)) is sent as `1753-01-01`, listing every record rather than none, and the empty-list notice never suggests an earlier date for it.
- **An empty search page inside the reachable window ends paging** ([#46](https://github.com/cyanheads/met-museum-mcp-server/issues/46)) with `truncated: false`, `remaining: 0`, and `nextOffset: null`, rather than repeating its own offset.
- **No error carries the Met's error page** ([#45](https://github.com/cyanheads/met-museum-mcp-server/issues/45)): `data.body` and `data.responseBody` are stripped from every HTTP failure, a 501, 505, or 4xx included.
- **The MCP Registry HTTP entry starts on HTTP**: `server.json` npm entries drop the `run start:*` arguments and set `runtimeHint: "npx"`, and the `streamable-http` entry fixes `MCP_TRANSPORT_TYPE` as `"value": "http"`.
